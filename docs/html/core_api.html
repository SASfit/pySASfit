Shared infrastructure: pysasfit.core

Used by several tools: data loading, instrumental resolution, background models, the preferences and project files.

Data loading

Data input for all pysasfit tools (same conventions as pyOZgui’s loadCurve).

pysasfit.core.io.load_data(filename, q_scale=1.0, skip_nonpositive_sigma=True, qmin=None, qmax=None)[source]

Read columns q, I, sigma [, dq] from a text file.

Conventions shared with pyOZgui (polydisperse_fit.loadCurve):

  • whitespace-, comma-, semicolon- or tab-separated columns; comment lines starting with #, % or // and unparsable header lines are skipped;

  • rows with non-finite values or q <= 0 are dropped, the data are sorted by q;

  • a FOURTH column is the q resolution, read as the Gaussian SIGMA of the resolution function (not the FWHM; use Resolution(..., fwhm=True) if the reduction writes FWHM).

q_scale converts units (e.g. 0.1 for 1/nm -> 1/Angstrom); it is applied to q and dq. Returns (q, I, sigma, dq_or_None).

Instrumental resolution

The pinhole operator is the same as in the OZ tools (Rician kernel by default, Gaussian as an option).

Instrumental smearing.

Because the model intensity is quadratic in rho, smearing cannot be applied to the amplitude. A resolution object instead provides a fine q-grid q’ and a matrix R such that

I_smeared(q_i) = sum_m R_im I(q’_m).

Then C_i = sum_m R_im c(q’_m) a(q’_m) a(q’_m)^T in Hansen’s notation.

class pysasfit.core.resolution.Resolution(dq, kernel='rician', fwhm=False, nSigma=3.0, oversample=3)[source]

Bases: object

Pinhole Q-resolution as a fixed linear operator – the same operator as pyozgui.polydisperse_fit.Resolution (pyOZgui), so both programs smear identically.

kernel="rician" (default) or "gaussian".

Rician is the physically correct kernel: the instrument broadens Q isotropically in the two-dimensional detector plane and the data are then radially averaged, so the distribution of the magnitude |Q| about the nominal Q0 is

P(Q|Q0) = (Q/s^2) exp(-(Q^2 + Q0^2)/2s^2) I0(Q Q0/s^2),

evaluated as (Q/s^2) exp(-(Q-Q0)^2/2s^2) i0e(Q Q0/s^2) to avoid overflow. A Gaussian in Q is its Q0/s >> 1 limit; it is adequate for small dQ/Q but puts weight at Q < 0 for large dQ/Q (lowest-Q points). The factor Q makes the Rician weight vanish at the origin.

Conventions (identical to pyOZgui):

  • dq is the kernel’s SIGMA; fwhm=True converts a FWHM (/2.3548).

  • The model is evaluated on an extended grid Qext = linspace(lo, hi, oversample*M) united with the measured Q, lo = max(min(Q - nSigma dQ), 1e-3 Q_min), hi = max(Q + nSigma dQ); including the measured Q makes dQ -> 0 reproduce the unsmeared curve exactly.

  • Trapezoid weights on Qext; every row normalised to 1; a row that falls between grid points falls back to the nearest node.

  • The background is NOT smeared (it is added after smearing, in the model).

dq may be a scalar or an array with one value per data point.

class pysasfit.core.resolution.SlitResolution(c, n_nodes=16)[source]

Bases: object

Slit smearing with a Gaussian beam-length profile (Glatter 1977; Hansen 2016, sect. 3.1).

I_m(q) = 2 int_0^infty P(t) I(sqrt(q^2 + t^2)) dt, P(t) = exp(-t^2 / c^2) / (c sqrt(pi)) (2 int_0^infty P = 1)

c is the profile width in q units. The t-integral is done with Gauss-Hermite (half-range) quadrature.

Background models

Background models added to the particle scattering.

I_model(q) = (smeared) c(q) F(q)^2 + B(q; theta)

The background parameters theta can be linear (constant, amplitudes) or nonlinear (power-law exponent, correlation length). They are not regularised: they are extra columns of the Gauss-Newton Jacobian with a flat prior and are integrated out in the Laplace approximation of the evidence, exactly like the flat background of Hansen (2016).

Positive parameters (amplitudes, exponents, lengths) are fitted as z = ln(theta), which keeps them positive and makes the Gaussian approximation better behaved. The background is evaluated at the measured q (not smeared).

Built-in terms

Constant          c
PowerLaw          A q^(-n)                 (low-q upturn of large aggregates, Porod n = 4,
                                            mass fractals 1 < n < 3, surface fractals 3 < n < 4)
OrnsteinZernike   I_L / (1 + (q xi)^2)     (concentration fluctuations / network blobs)
FunctionTerm      any user function f(q, *theta) with a numerical Jacobian

Example:

bg = Background([Constant(), PowerLaw(n=4.0, fit_n=False)])
fit = DensityProfileFit(q, I, s, background=bg)

Preferences

The settings themselves are listed, with explanations, in Preferences (Settings → Preferences…).

User preferences: numerical settings that are not on the tools’ main panels.

Every entry is declared once in pysasfit.core.settings_schema with its factory default and a label; the explanation of each entry is in pysasfit.core.settings_help. The user’s values live in one JSON file:

Windows:  %APPDATA%\pySASfit\settings.json
Linux/macOS:  $XDG_CONFIG_HOME/pysasfit/settings.json  (default ~/.config/...)
override: environment variable PYSASFIT_SETTINGS=<path>

Only values that differ from the factory default are written, so a later change of a factory default reaches every user who has not set that entry.

The GUIs read the values when a calculation starts (get/values) and pass them explicitly to the library; library functions keep their own documented defaults, so scripts are not affected by the preferences file.

Projects and last session

Project files and the automatic last session of the GUI tools.

A project holds everything needed to reopen a piece of work: the data (path and an embedded copy of the numbers), the settings of every panel control and the last result. The same file format serves two purposes:

  • projects – File → Save project… / Open project… (*.pysasfit), written only when the user asks;

  • the last session – session_<tool>.pysasfit next to the preferences file (pysasfit.core.settings.settings_path()), written automatically after loading data, after a fit and when the window closes, and reopened at the next start. Settings → Forget last session deletes it.

File format (a ZIP archive)

project.json

format = "pysasfit-project", format_version (integer, see FORMAT_VERSION), tool, app_version, saved (ISO time), data (original path, size/mtime signature, column names), controls ({name: {"kind": ..., "value": ...}}, one entry per panel control) and extra (tool-specific plain values).

data.npz

the data columns as read (q, I, sigma[, dq]) – the project still opens when the original data file has moved or changed.

result.pkl

the last result as a Python pickle (optional). It is only needed to show the result without fitting again; if it cannot be read (e.g. after an incompatible change of the result classes) the project opens without it.

Compatibility rules

  • Reading never relies on a key being present. Before the controls are restored, the window is reset to its factory state, so every control that a file does not mention – e.g. a parameter added in a later version – keeps its default value.

  • Controls in the file that the program does not know (from a newer version) are ignored, and so are values a control does not accept.

  • format_version is raised whenever the meaning of an existing entry changes; upgrade() converts older files step by step (version 1 is the first version, nothing to convert yet). A file with a newer format_version than this program is still read, with a warning.

pysasfit.core.project.FORMAT_VERSION = 1

Version of the project format. Raise it when the meaning of an existing entry changes and add the conversion to upgrade(). New entries need no new version: missing entries take their default values when read.

Detachable panels

Detachable panels for the Qt main windows.

Every panel (input controls, each plot, text output) is a QDockWidget. Inside the main window it can be moved to another side or stacked as tabs by dragging its title bar. The detach button in the title bar (or a double-click on the title) moves the panel into an ordinary, independent window: own task-bar entry, minimise / maximise, and it does not stay on top of the main window (Qt’s own floating docks are tool windows that always stay above their main window). Closing such a window docks the panel again. Every panel has a border (View → Panel border: raised (default), sunken, groove, line or none), docked or detached; the active panel (last clicked or holding the keyboard focus) is framed in colour. View → Arrange panels puts the docked panels side by side, one above the other, in a grid or all as tabs, and cascades or tiles the detached panel windows. Panels can be hidden and shown from the View menu; View → Reset layout docks everything in the arrangement the window started with (optional panels hidden at the start are hidden again). The arrangement, including detached windows and their positions, is part of the last session (dock_state).

Detachable tabs

Used by the launcher and by pyTOOLbox (see The launcher: all tools in one window).

Tab widget whose tabs can be detached into independent windows and attached again.

Used by the pySASfit launcher (one tab per tool) and by tools with tabs of their own (pyTOOLbox). Any QTabWidget can be replaced by DetachableTabWidget; nothing else changes for the pages.

Detach a tab by

  • dragging it out of the tab bar,

  • double-clicking it,

  • the tab bar’s context menu (right click), or

  • DetachableTabWidget.detach() / the launcher’s View menu.

A detached tab is an ordinary top-level window (own task-bar entry, minimise / maximise, not kept above the main window). A page that is a QMainWindow (every pySASfit tool) becomes the window itself and shows its own menu bar again; any other page gets a small window around it. The Attach button in the window’s menu bar (or simply closing the window) puts the tab back at its original place. The context menu of the tab bar lists the detached tabs and has “Attach all”.

DetachableTabWidget.state() / restore_state() give the detached tabs and their window geometries as plain JSON data, for the last session.

A tab can show a coloured wordmark instead of its plain text (DetachableTabWidget.set_wordmark(), e.g. the logo labels of the pySASfit tools: grey “py”, bold core in the tool’s colour, grey ending). The plain text stays the tab’s name (tabText), used for menus, window titles and the last session.

Colour scales of detector images

Colour scales for 2D detector images.

norm = make_norm(“asinh”, image) ax.imshow(image, norm=norm)

The scales:

linear   I
log1p    log(1 + I)       counts: zero stays finite, small counts are spread out
symlog   linear for |I| < 1, logarithmic above (also negative values, e.g. after subtraction)
asinh    asinh(I)         like symlog but smooth at the transition

The threshold of symlog / asinh (linear_width) is 1 in the units of the image, i.e. one count for raw data.
