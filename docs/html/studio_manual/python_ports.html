Python ports of SASfit plugins

pysasfit.studio.ports holds vectorised numpy versions of SASfit C plugin functions. They take the same parameter vector as the C function, evaluate all q at once and, for ψ-dependent (anisotropic) functions, also a grid of directions ψ of Q on the detector:

import numpy as np
from pysasfit.studio import ports

spec = ports.get("ff_deformed_ring_polymer__bz_")
p = np.zeros(50); p[:6] = [30.0, 8.0, 0.55, 2.0, 20.0, 75.0]   # Rg_ll, Rg_perp, nu, I0, theta_0 (deg), psi (deg)
q = np.logspace(-2, 0.5, 200)
I = spec(q, p)                                             # psi from p[5]
psi = np.linspace(0, np.pi, 32, endpoint=False)
I2d = spec(q[None, :], p, psi=psi[:, None])                # (32, 200): psi in radians, broadcast against q

The C plugins remain the default and the reference. ports.enable() (or ports.enable(["ff_..."])) makes studio.function(name) and the explorer use the ports instead; ports.disable() switches back.

Using the ports

Every port is registered under its own name ff_py_<name without ff_> next to the C function, in the collection “py plugin ports”; the model explorer shows them in the form-factor menu tree py plugin ports (a copy of the SASfit plugin tree). From a script:

from pysasfit.studio import function
f_py = function("ff_py_sheared_cylinders__maier_saupe_")   # Python port
f_c = function("ff_sheared_cylinders__maier_saupe_")       # C plugin

ports.enable() instead replaces the C plugins under their original names (scripts, comparisons).

Comparison with the C plugins

python -m pysasfit.studio.ports.check                       # all ports
python -m pysasfit.studio.ports.check ff_ringpolymerBZ --sets 50 --report ports_report.md

or, from the repository root without installing and with a chosen SASfit folder:

python tools/port_check.py --lib-dir C:/Users/me/SASstudio --sets 30 --report ports_report.md
python tools/port_check.py --list
python tools/port_check.py --aniso 1e-9          # tighter SASfit precision for this run

Freshly built plugins can be taken directly from the SASfit source tree, without copying the DLLs: python tools/port_check.py --plugin-dir /c/Users/<you>/switchdrive/SASfitGit/src/plugins (session only), or once for all pySASfit sessions pysasfit-studio plugin-build-dir /c/Users/<you>/switchdrive/SASfitGit/src/plugins (saved; --clear forgets it). Every <dir>/<plugin>/lib/libsasfit_<plugin>.dll then replaces the installed plugin of the same name and <dir>/<plugin>/include/sasfit_<plugin>.h the bundled header; libsasfit itself still comes from the SASfit installation.

SASfit plugins integrate with sasfit_integrate, whose relative tolerance is SASfit’s eps aniso (studio default 1e-5), not eps nriq. For such functions tools/port_check.py compares at max(port tolerance, 2·eps aniso), so a deviation of ~1e-6 with eps aniso = 1e-5 is SASfit’s requested precision, not an error.

For every port, random parameter sets within PortSpec.sample are evaluated with the port and with the C plugin of the SASfit library (SASfitFunction(name, language="c")) on q = 10⁻³ … 10 nm⁻¹ (with Rg = 1 … 100 nm: q Rg = 10⁻³ … 10³). The report gives the largest relative deviation, the times of both implementations, a check that the vectorised ψ argument equals the ψ parameter, and the number of points where the C function returned 0 but the port did not (a failed integration in C). The C side uses your SASfit integration settings (Settings → Integration…), so integration-based functions are compared at SASfit’s own precision.

The test suite (tests/studio/test_ports.py) compiles the unchanged C sources of the ported functions (tests/studio/port_reference/sasfit_src) with small shim headers and GSL, with a reference-quality sasfit_integrate, and checks the ports against them, against closed forms (Debye function, Dawson integral of the Gaussian ring) and against the large-q asymptotics.

Sheared objects (ports/sheared.py): core-shell cylinders and spheroids with an orientation distribution p(θ, φ) and a log-normal size distribution. Methods and speed (2026-11-18).

  • Legendre method (default): A²(q, γ) is expanded in Legendre polynomials of cos γ, a_l(q) = ∫ A² P_l dt, and I(q, ψ) = Σ_l (l+½) a_l(q) g_l(ψ) with g_l(ψ) = ∫ p(û) P_l(û·q̂) dΩ. For the axially symmetric distributions g_l = p_l P_l(cos ψ) (addition theorem) with the moments p_l of p(θ); for Hayter-Penfold from the Fourier series of p in φ (even m) and normalised associated Legendre functions (cost ~ l·m·n_θ; the θ, φ quadrature only above l = HP_LMAX). Per q only a 1D integral over cos γ is needed (l up to ~1.2 q D + 40), and every ψ costs a Legendre sum: a 64 × 36 map takes 0.01 s (σ = 0) instead of ~1 s. Agrees with the quadrature method to ~1e-12.

  • Size average: A(q, γ; ν) = ν³ A(qν, γ; 1), so I(q) = Σ_k w_k ν_k⁶ I₁(q ν_k). The ν nodes (composite Gauss-Legendre in ν) resolve the oscillations of I₁(q ν) in ν, ~3 per period π/(q D). Correction: the 24-node Gauss-Hermite rule used until 2026-11-18 did not; for σ > 0 the ports were off by 4e-4 at q D ≈ 13 and up to tens of percent at q D ~ 100 (the comparison with C only sampled σ = 0).

  • Schulz-Zimm (size_dist="schulz", ports ff_sheared_{cylinders,spheroids}__<kind>__schulz_, Python only): mean 1, relative standard deviation σ < 1. For spheroids the size average of A² is analytic (series and closed forms of the sphere block, pysasfit.scatter.blocks, Wagener & Förster 2023), for cylinders by ν nodes.

  • Quadrature method (method="quadrature", as the C plugin): θ, φ double integral; with Numba as a compiled kernel in parallel over the q points (ports/_sheared_numba.py, J₁ from Cephes as in SciPy). Choose with sheared_intensity(..., method=..., backend=...), sheared.METHOD / PYSASFIT_SHEARED_METHOD, sheared.BACKEND / PYSASFIT_SHEARED_BACKEND.

Observations on the C code made while porting, and the fixes made in the SASfit sources on 2026-11-17 (src/plugins/polymer_rings/sasfit_ff_ringpolymerB{MB,Z}.c, src/plugins/deformed_polymers/*.c; they take effect after rebuilding the SASfit plugins):

  • Rings (BMB, BZ): the kernels exp(-μ (x(1-x))^a) are concentrated in a layer of width μ^{-1/a} at the end points for large q Rg. Adaptive integration over [0, 1] misses it. SASfit (default settings) gave wrong values from q Rg ≈ 350 on and 0 beyond. Plain GSL QAGS failed from q Rg ≈ 30, CQUAD was off by ~1e-3 at q Rg ≈ 45. Fix: the exponent is symmetric under x → 1-x, so P = 2 ∫_0^{1/2} exp(-μ s(x)) dx, and the upper limit is cut where μ s(x) > 45. Now plain QAGS gives 1e-9 up to q Rg = 10³, and the C functions are 3–10× faster.

  • Deformed generalized Gaussian chain: the Guinier approximation exp(-β/3) for √β < 0.1 (error up to ~4e-6) and the cancellation just above it were replaced by the exact series for u < 1. C and port now agree to 1e-14.

  • Deformed rings:

    • the psi < 0 check read the scratch value p[MAXPAR-1] before it was set; it and the theta_0 < 0 check were removed (any angle is allowed);

    • the parameter structure passed to the ring function is now initialised with sasfit_init_param, and its errors are passed on.

Parameter domains and default values

Every port has a description of its parameters, spec.params (:mod:pysasfit.studio.ports.params): for each parameter its domain (lower/upper bound, open or closed), a default value and a kind (length, sld, intensity, angle, exponent, count, fraction, dimensionless, dummy; lengths in the unit reciprocal to q, the numbers chosen for q in nm⁻¹). It comes from

  1. ports/param_table.py, generated by python tools/gen_port_params.py: the names of the plugin headers and the bounds parsed from the SASFIT_CHECK_COND* domain checks of the C sources (a check of one parameter against a number becomes a bound, other checks become rules), kinds guessed from the names;

  2. default values by kind;

  3. ports/param_defaults.py: hand-written defaults and corrections (per parameter name and per port).

Derived from it:

  • spec.check(p) / spec.validate(p): the domain check with the C messages (R(-3) < 0); the Python functions call it once per evaluation, so an invalid value gives the same error as the C plugin;

  • spec.defaults(): the default vector; the explorer starts new contributions with it (ff_py_*);

  • spec.suggest(q, I): values suggested for measured data: all lengths scaled together so that the largest is 2/q_mid (q_mid: geometric mean of the q range), then I0 (or the contrasts) matched to the data at low q. The explorer button Suggest from data does the same for any function (also C plugins: kinds guessed from the names) and sets the scale (or the amplitude N of the size distribution).

python tools/write_header_defaults.py <SASfitGit/src/plugins> writes the defaults and domains into the parameter tables of the plugin headers: every row gets, after the description, a cell with the default value and one with the domain (syntax agreed 2026-11-24)::

 *       <td>\b R_c</td>
 *       <td>core radius containing solvent</td>
 *       <td>(default=10)</td>
 *       <td>[0;+inf)</td>

The domain uses ;, +inf / -inf, square brackets for closed and round brackets for open bounds; a bound may also be the name of another parameter ([0;R_c]). A row without description keeps an empty description cell, so the order is name, description, default, domain. Values already in the header that differ from the port are kept (set by hand; the tool reports them so that the port can follow, --force overwrites). The pySASfit header parser reads the cells in any order after the name; the older paragraph \par Default values and domains: is obsolete, removed from all headers and only read as a fallback.

Systematic check (2026-11-24). The defaults and domains are written for every ported plugin function (267 functions in 44 plugin headers; the Python-only variants ff_sheared_*__schulz_ and the libsasfit core functions have no plugin header). Every port is checked at its defaults: each default lies inside its domain and satisfies the rules between parameters, and the function is finite, not identically zero and (form factors) not negative on q = 1e-3 … 10. Reading the written headers back with the pySASfit parser gives exactly the defaults and domains of the ports. write_header_defaults.py writes only the parameters listed in the header table (trailing unused parameters of a port are left out; other count differences are reported, not written) and 12 significant digits for the bounds. Domain policy: lengths, radii, widths ≥ 0 (or > 0 where the function divides by them); scattering length densities, contrasts and excess scattering lengths are not restricted – the template checks eta < 0 / beta_r < 0 of SASfit’s plugin skeleton were removed from rod, flat/Porod cylinders, Kratky sphere, Teubner–Strey, the three pearl necklaces and the multilamellar vesicle (C and ports). Header fixes found on the way: missing </table> (sphere+R^-a ×3), malformed /td> (two thin_objects tables), an unterminated comment block and </tr></tr> (boucher_cyl), and the unused 8th parameter of the modified pearl necklace (was documented as g). Defaults set by hand in sasfit_sphericalshells.h (sphere, hollow sphere, spherical shells i–iii, multilamellar vesicle) were taken over by the ports, except ν of spherical shell ii (inner radius νR, the C code requires 0 ≤ ν < 1: default 0.8, domain [0;1)). Each new port batch runs the tool for its plugins.

Magnetic ports (2026-11-23)

ff_magnetic_shell_psi and ff_superparamagnetic_ff_psi (libsasfit core) are ported with an additional PortSpec.terms(q, p, psi) that returns the magnetic basis terms (NN, NM, MH, MSF, CH). The channel of a data set is then a setting of the data set, not a separate function (Polarised neutrons). Without a setting the ports give the SASfit result with their pol parameter; the comparison with the C functions runs as for every port. C fix: ff_magnetic_shell_cross wrote ψ = π/2 into the caller’s ψ parameter and read it as degrees (sin²ψ = 7.5e-4 instead of 1); it now uses ψ = 90°.

Writing a port

A port module defines functions f(q, p, psi=None) and a list SPECS of dictionaries with the fields of PortSpec (name, intensity, parameters, psi_index, sample ranges, tolerance, C source, notes); it is registered in ports._load(). Quadratures should be vectorised over q (e.g. ports.quadrature.tanh_sinh_01).
