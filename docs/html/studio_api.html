The narrative description is in studio reference. Importing the GUI modules needs PySide6, so only the modules that work without it are listed here.

Functions of the SASfit libraries

Calling SASfit model functions from Python.

from pysasfit import studio sphere = studio.function(“ff_sphere”) I = sphere(q, R=50.0, eta=1.0) # vectorised over q, named or positional parameters F = sphere.amplitude(q, R=50.0, eta=1.0) # the ‘_f’ function (non-squared amplitude) V = sphere.volume(50.0, R=50.0, dist=0) # the ‘_v’ function

A function is either a compiled SASfit plugin (described by the plugin headers, see pysasfit.studio.headers) or a Python plugin:

  • a file sasstudio_<name>.py in one of pysasfit.studio.paths.python_plugin_dirs() (format: templates/python_plugin.py), or

  • functions registered at run time with register_python_function(), among them the SasView models of the sasmodels package (ff_sv_<name>, sq_sv_<name>, pysasfit.studio.sasmodels_bridge).

A Python callable with the attribute vectorized = True gets the whole x array at once.

Python plugins take precedence, so a C plugin can be overridden for testing.

Models

Combining SASfit functions into models and fitting them (SASfit manual, ch. 4-5).

A ScatteringContribution is one population: a form factor P(q; x), optionally a size distribution N(x) over one form-factor parameter x and a structure factor S(q). With a size distribution:

  • "monodisperse" (manual 4.1.1): I = S(q) ∫ N(x) P(q;x) dx

  • "decoupling" (manual 4.1.2): I = ∫N P dx + (∫N F dx)² / ∫N dx · (S(q) - 1), F = scattering amplitude (the ‘_f’ function)

  • "lma" local monodisperse (4.1.3): I = ∫ N(x) P(q;x) S(q; R_V(x)) dx, with the first structure-factor parameter set to the volume-equivalent radius R_V = (3V(x)/4π)^(1/3) of the ‘_v’ function

  • without a structure factor: I = ∫ N(x) P(q;x) dx

The x integral is done on the support of N(x) (found automatically or given as x_range) with Gauss-Legendre nodes (default) or another method of pysasfit.studio.integration (method, n_x, rtol, atol, limit; scipy quad_vec, simpson, …). The integrals inside the SASfit functions follow pysasfit.studio.library.configure_precision().

A ModelFunction sums contributions (with scale factors) and an optional background (a pysasfit.core.background.Background or a constant), and optionally applies an instrumental resolution from pysasfit.core.resolution (Rician pinhole, slit, …).

transform (SASfit’s transform menu, pysasfit.studio.hankel) turns the scattering of the particles into what an instrument measures:

  • None – I(q) itself;

  • a SESANSTransform – the model is evaluated at spin-echo lengths δ (passed instead of q) and gives G(δ) - G(0) or P/P0; the constant background is an offset of G(δ) - G(0), the power-law term is unused;

  • a MSASTransform – multiple small-angle scattering of a sample of the given thickness, before resolution and background.

polarisation (a Polarisation, a dictionary for it, or None) says what a data set measured with polarised neutrons (unpolarised, flipper off / on not corrected, I+, I-, I- - I+, the four channels): magnetic functions return their basis terms and the model weights them; non-magnetic contributions count with the nuclear weight (0 in the spin-flip channels and the difference); C functions with a pol parameter get SASfit’s pol (moment labels) = n- - n+ of the setting (+/- = neutron spin).

A transform may also be given as a dictionary or name for make_transform(), e.g. transform={"kind": "msas", "thickness": 0.1, "wavelength": 0.6}.

Pipeline holds data sets and model functions and fits named parameters with scipy.optimize.least_squares:

pipe = Pipeline()
d = pipe.add_dataset("test.dat")
sc = ScatteringContribution("ff_sphere", {"R": 50, "eta": 1},
                            size_distribution="sd_LogNorm", sd_params={"N": 1, "s": 0.1, "p": 1, "mu": 50},
                            distributed="R")
m = pipe.add_model(ModelFunction([sc], background=0.0), dataset=d)
res = pipe.fit(m, ["0.sd.N", "0.sd.mu", "0.sd.s", "background"])

SESANS and multiple scattering (Hankel transforms)

Hankel transforms for SESANS and multiple small-angle scattering (MSAS) in pySASstudio.

This is the Python counterpart of the transform menu of SASfit (sasfit_old/sasfit.c: Gztransform, imMSAStransform, integral_IQ_incl_Gztransform):

SASfit

here (make_transform())

1

None – the scattering intensity I(Q)

H{...}/2pi

"sesans" – G(δ) - G(0) = 1/(2π) ∫ I(Q) [J0(Qδ) - 1] Q dQ

Exp(H{...}/2pi)

"sesans_p" – P/P0 = exp(λ² t [G(δ) - G(0)]) (λ = t = 1 gives SASfit’s exp(G(δ) - G(0)))

MSAS

"msas" – intensity with multiple small-angle scattering

Units. SASfit functions carry none, so the user keeps them consistent (as in SASfit): with I(Q) in cm⁻¹ the sample thickness thickness is in cm and the wavelength wavelength is in the reciprocal unit of Q (nm for Q in nm⁻¹, Å for Q in Å⁻¹). G(δ) - G(0) then has the unit cm⁻¹ · [Q]² (Å⁻²cm⁻¹ for Q in Å⁻¹, the SasView / .ses convention) and λ² t G is dimensionless.

SESANS (Rekveldt 1996; Andersson et al., J. Appl. Cryst. 41, 868 (2008)): the measured polarisation is P(δ)/P0 = exp(λ² t [G(δ) - G(0)]), and G(0) λ² t = Σ t is the total small-angle scattering probability.

MSAS (Schelten & Schmatz, J. Appl. Cryst. 13, 385 (1980); SASfit imMSAStransform). With φ(r) = λ² t G(r), τ = φ(0) = Σ t and k0 = 2π/λ, the scattered intensity of a slab of thickness t is

I_MSAS(Q) = c · k0² / (2π t) ∫ [exp(φ(r)) - 1] J0(Q r) r dr,

c = exp(-τ) when the data are normalised to the incident beam (SASfit’s MSAS) and c = 1 when they are normalised to the measured transmission, which already contains the loss exp(-τ) by small-angle scattering (norm). The single- scattering term is split off and evaluated directly,

exp(φ) - 1 = φ + ψ, ψ = exp(φ) - 1 - φ, I_MSAS = c [ I(Q) + k0²/(2π t) ∫ ψ(r) J0(Q r) r dr ],

so that only the (smooth, fast decaying) multiple-scattering part goes through the numerical transforms.

Numerics. Both transforms use the same quadrature: the integrand f(k) k is linear between the nodes of a logarithmic grid and every interval is integrated exactly against J0 (∫J0 by Struve functions, ∫k J0 = k J1 / x). This is a Filon-type rule: the oscillation of J0 needs no sampling, only I(Q) (or ψ(r)) itself must be resolved by the grid. The weights depend only on the grid and the output points, so they are computed once and every evaluation during a fit is one matrix-vector product. Below the first node f is taken as constant (Guinier plateau); above the last node an optional power-law tail f ∝ k^-p (default p = 4, Porod) completes the zero-order moment ∫ f k dk.

pysasfit.studio.hankel.hankel_weights(x, k, kernel='j0', tail_low=True, tail_power=None, k_upper=None)[source]

Weights W with W @ f(k) ≈ ∫_0^∞ f(k) K(k x) k dk for all x (a matrix len(x) × len(k)).

kernel: "j0" (K = J0) or "j0m1" (K = J0 - 1, the SESANS kernel; finite also for f ∝ k^-p, 2 < p). f(k) k is taken as linear between the nodes k (increasing, > 0) and each interval is integrated exactly. tail_low: f(k) = f(k_0) on [0, k_0]. tail_power = p > 2: f(k) = f(k_N) (k/k_N)^-p above the last node. k_upper (a number or one per x): the integral of that row ends there (instrument resolution / acceptance of SESANS). The limits should be nodes of k: intervals above the limit are dropped, a row with a limit below the last node gets no power-law tail.

class pysasfit.studio.hankel.FFTLogPlan(n, dln, offset)[source]

Bases: object

The FFTLog transform of one grid, precomputed once: (T @ a)[j] = ∫ a(k) J0(k x_j) x_j dk.

FFTLog is a circular convolution in ln k: T[j, i] = c[(i + j) mod n], so the n numbers c (the transform of a unit vector) define it completely. The plan keeps their spectrum; apply() is then two real FFTs of length n (no matrix), and matrix() builds T from c by indexing (no FFTs). Plans are shared between transforms with the same grid. A length n that is not a fast FFT length is used as given; a warning names the nearest fast ones.

Polarised neutrons

Polarised neutrons: what a data set measures, as a setting of the data set instead of separate functions.

SASfit has one function per polarisation channel (_pp, _mm, _pm, _POLARIS, _cross, …) and the efficiencies as parameters of every model. Here a magnetic model returns its basis terms once,

NN = <|N|²> nuclear NM = <Re N M⊥h*> nuclear-magnetic interference (h: field axis) MH = <|M⊥h|²> magnetic, non-spin-flip MSF = <|M⊥|² - |M⊥h|²> magnetic, spin-flip CH = <Im(M⊥a M⊥b*)> chiral (0 unless the model is chiral)

(per (q, ψ), ψ = angle between q and the field on the detector; M = magnetisation, i.e. moment density), and the data set says what was measured (Polarisation).

Convention (Moon, Riste & Koehler, Phys. Rev. 181, 920 (1969)): + and - are the neutron spin parallel / antiparallel to the field (σ_z|±> = ±|±>, z along the field). The neutron moment is opposite to its spin, so the amplitudes are U±± = b ± p M⊥z: spin parallel to the magnetisation adds the magnetic amplitude. The ideal cross sections are

I++ = NN + MH + 2NM, I– = NN + MH - 2NM, I+- = MSF - 2CH, I-+ = MSF + 2CH, SANSPOL I± = I±± + I±∓ = NN + MH + MSF ± 2NM ∓ 2CH, I- - I+ = -4NM + 4CH.

Michels and the SASfit C functions (_pp, pol = +1) label the states by the neutron moment: their “++” is “–” here, their pol is -(n+ - n-) here.

and, for data that are not corrected for the instrument, the mixing of I+ and I- with the beam polarisation P, the flipped fraction f of the flipper and the depolarisation of the sample (P_f), exactly as in pysasfit.sasred.polarisation:

flipper_off_is_plus says which flipper state is + (spin parallel to the field). Non-magnetic contributions enter with the NN weight (1, or 0 in the spin-flip channels and the difference). A model gets the setting as ModelFunction.polarisation; while it is evaluated the setting is active (active()) and magnetic functions read it (current()). Without a setting a magnetic port behaves like its SASfit original (its pol parameter in SASfit’s moment labels: I = (1+pol)/2 I- + (1-pol)/2 I+ here); C functions with a pol parameter get pol = n- - n+ of the setting (SANSPOL quantities only).

Parameter addresses for fits: pol.P, pol.f, pol.P_f, pol.psi_H.

SasView models (sasmodels)

The models of SasView (the sasmodels package, pip install sasmodels) as pySASstudio functions.

Every sasmodels model becomes a function next to the SASfit plugins: ff_sv_<name> for form factors and shape-independent models, sq_sv_<name> for structure factors (menu groups “SasView: <category>”). They take part in everything the studio does with SASfit functions: mixtures, size distributions (the studio integrates over a parameter itself; sasmodels’ polydispersity is not used), structure factors with the decoupling approximation or the local monodisperse approximation, fits, SESANS / MSAS transforms, projects and “Copy Python”.

Convention (SASfit, chosen 2026-11-13): a form factor is the intensity of one particle,

P(q) = (Δρ V F(q))² = ⟨F²⟩ of sasmodels = V · I_sasview(q; scale = 1, background = 0),

not SasView’s per-volume intensity I_sasview = scale/V · (Δρ V F)². So with a size distribution N(x) the integral ∫ N(x) P(q; x) dx weights the sizes as for the SASfit plugins (V², not V), and N is a number density. The amplitude is ⟨F⟩ (decoupling approximation), the volume the form volume of sasmodels (LMA). Models without an amplitude in sasmodels (e.g. the shape-independent ones) have V = 1 there, so P = I_sasview.

Units: sasmodels works in Å (q in 1/Å, lengths in Å, SLDs in 10⁻⁶/Å², I in 1/cm). The studio’s functions carry no units, so set_length_unit() says in which length unit q and the length parameters are given (“nm” for q in 1/nm, as the explorer’s q unit); the bridge converts q, every parameter with a length unit (Å, Å², Å³) and the volume. SLD parameters stay in 10⁻⁶/Å² (the unit SasView uses). Then P(q) = 10⁻⁴ (Δρ V F)² in cm⁻¹ · [length]³: a number density N in 1/[length]³ gives I = N P in 1/cm.

Parameters: sasmodels’ scale and background are fixed at 1 and 0 (the studio has its own). Vector parameters (sld[n], thickness[n] of core_multi_shell) become numbered parameters sld1 … sld10; orientation angles (2D only) and magnetic parameters are left out. Models with more parameters than SASfit’s MAXPAR (50) are skipped. SasView’s size distributions (gaussian, lognormal, schulz, rectangle, uniform, boltzmann of sasmodels.weights) are sd_sv_<name> with the parameters N, center, width (σ/center) and nsigmas (see DISTRIBUTIONS). The C kernel of a model is compiled on first use (sasmodels needs a C compiler; on Windows the tinycc package or gcc of MSYS2).

Fitting engine and optimisers

FitProblem is the engine behind the Fit panel. The optimiser backends are listed in BACKENDS; available_backends() returns those whose package is installed, and register_backend() adds another one.

Fitting model functions to one or several data sets.

A FitProblem couples data sets with models (ModelFunction) and a table of fit parameters:

  • a common parameter drives the same model parameter in several (default: all) data sets;

  • a local parameter belongs to one data set only (add_local creates one per data set);

  • a global parameter (add_global, e.g. P1) is not a model parameter itself: link makes model parameters of any contributions and data sets follow it, each as factor * P1 (SASfit’s global parameters with a factor); constraints and priors may use it like any other parameter;

  • fixed parameters keep their value, lower/upper are bounds;

  • constraints are inequalities or equalities of the parameter names ("ff_R + ff_t < 100", "scale_0_a + scale_0_b == 1"): the label of a parameter with every run of non-word characters turned into _, and a c in front if it starts with a digit (1.sd.mu -> c1_sd_mu), see FitProblem.identifiers();

  • priors (add_prior, add_prior_text) add a term to chi^2: normal (mean, sigma), lognormal (median, factor > 1), halfnormal (sigma, for x >= 0) as extra residuals, and loguniform (flat in ln x, lower bound > 0 needed) as a scalar term 2 ln x that the least-squares backends (scipy, dfols) cannot use.

Parameters are addressed like in Pipeline: "background", "scale.<i>" and "<i>.<ff|sd|sq>.<name>" for contribution i of a model; "transform.thickness" and "transform.wavelength" for a model with a SESANS or MSAS transform (pysasfit.studio.hankel); "pol.P", "pol.f", "pol.P_f", "pol.psi_H" for a model with a polarisation setting (pysasfit.studio.polarisation). A data set of a SESANS model has the spin-echo lengths in place of q. Variable projection leaves the parameters of data sets whose model is not linear in the scales (SESANS P/P0, MSAS) to the optimiser.

prob = FitProblem() prob.add_dataset(“a.dat”, model_a, name=”a”) prob.add_dataset(“b.dat”, model_b, name=”b”) prob.add_common(“0.ff.R”, lower=1, upper=200) # same radius in both data sets prob.add_local(“scale.0”, lower=0) # one scale factor per data set prob.add_local(“background”) prob.add_constraint(“scale_0_a + scale_0_b == 1”) # labels ‘scale.0[a]’, ‘scale.0[b]’ result = prob.fit(“scipy”) # or prob.fit(“nlopt”, “LN_BOBYQA”) print(result.text())

Backends (see available_backends() for those installed): "scipy" (scipy.optimize.least_squares()), "scipy-global", "nlopt" (any NLopt algorithm, chi^2 as scalar objective), "iminuit", "bumps", "cma" and "dfols" (DFO-LS, derivative-free least squares). More can be registered with register_backend(). The residuals are (model - data) / sigma; the uncertainties come from the numerical Jacobian at the optimum for every backend.

Two options speed up fits of mixtures and size distributions (both off by default, results are the same):

  • vp=True – variable projection: the parameters the intensity is linear in (background, scale.<i> and the amplitude N of a size distribution) are not searched by the optimiser; for every trial of the other parameters they are obtained exactly by linear least squares (bounds respected). Linear parameters that appear in a constraint or a prior stay with the optimiser. The errors are those of the full problem.

  • cache=True – form-factor cache: the intensity of a contribution and the form factor on the integration nodes are remembered, so a change of one contribution does not recompute the others and a change of the size distribution does not recompute the form factor. snap (default 0.05) rounds the automatically found integration range outwards to a geometric grid of that relative step, so that the nodes are reused.

Models evaluated for different data sets may be the same object: the values of the parameters of a data set are set in the model right before it is evaluated. After a fit the models hold the values of the first data set (FitProblem.apply(k) sets those of data set k).

Saving a fit result

CSV, Excel (with charts) and the summary figure; the size distributions N(x) and N(x)·x^p are included, dist_power is the exponent p (the explorer’s size-distribution dock sets it).

Save a fit result: an Excel workbook (.xlsx) or CSV files.

The workbook has the sheets

  • Summary: optimiser, convergence, chi², chi²/dof, degrees of freedom, evaluations, time, data sets;

  • Parameters: value, error, bounds, fixed, at a bound, MINOS / posterior intervals;

  • Correlation (colour scale from -1 to 1) and Covariance of the free parameters;

  • Curve (one sheet per data set): q, I(q), sigma, fitted I(q), residual (fit - data) / sigma, with an Excel chart (log-log) of data and fit;

  • Distributions (only if the model has a size distribution): x, N(x) and N(x) x^p of every fitted distribution (p: the weight set in the explorer, default 3), with a chart;

  • Plot: the one-page summary picture (data, fit, residuals, size distribution N(x) x^3, parameters, correlation matrix; needs matplotlib and Pillow);

  • Report: the text of the Result tab.

CSV files (<name>_parameters.csv, _correlation.csv, _covariance.csv, _curve.csv, _distributions.csv (only with a size distribution), _plot.png) can be read by every program; save_csv("fit.csv", ...) writes fit_parameters.csv etc. Use delimiter=";" for Excel with a German or Swiss locale. save_figure writes the one-page summary as PDF, PNG or SVG; figure_bytes gives it as bytes (for the clipboard).

from pysasfit.studio import export result = problem.fit(“scipy”) export.save_xlsx(“fit.xlsx”, result, problem) # png=None: the summary picture is made if matplotlib is there export.save_csv(“fit.csv”, result, problem) export.save_figure(“fit.pdf”, result, problem)

Where the libraries, headers and plugins are

Where pysasfit.studio finds the SASfit libraries, plugin headers and Python plugins.

Search order for the compiled SASfit libraries (libsasfit plus the GSL, FFTW and compiler runtime it needs, and plugins/libsasfit_*):

  1. the folder set with set_lib_dir() at run time, or saved by the GUI (explorer: Settings -> SASfit installation; stored in ~/.pysasfit/studio_settings.json);

  2. the environment variable PYSASFIT_SASFIT_LIB;

  3. the environment variable SASFIT_LOCATION (as used by sasfit-collab);

  4. sasfit_lib/ inside this package (filled by pysasfit-studio install-binaries).

Every entry may name the folder holding libsasfit itself or a SASfit installation around it: <dir>, <dir>/lib, <dir>/bin and <dir>/sasfit_lib are tried (and the parent of a plugins folder). The plugin libraries are looked for in <lib>/plugins and in <lib>. A folder that does not contain libsasfit is skipped, so a wrong entry falls through to the next one. Nothing depends on the current working directory.

Plugin libraries can also come from a SASfit source/build tree (set_plugin_build_dir(), saved setting plugin_build_dir, environment variable PYSASFIT_PLUGIN_BUILD_DIR), e.g. SASfitGit/src/plugins: every <dir>/<plugin>/lib/libsasfit_<plugin> found there is used instead of the library of the same name in <lib>/plugins, and <dir>/<plugin>/include/sasfit_<plugin>.h instead of the bundled header. libsasfit itself still comes from the library folder above.

The menu structure of the functions comes from Doxygen group files *.def, found by def_dirs() (<lib>/plugins/def and the like); see pysasfit.studio.groups.

Menu tree of the functions

Menu tree of the SASfit model functions, from the Doxygen group definitions (*.def).

SASfit builds the pull-down menus for form factors, structure factors and size distributions from two sources:

  • the *.def files of the plugin directory (a folder def next to the plugin libraries, or the plugin folder itself, see pysasfit.studio.paths.def_dirs()) define the groups and how they nest:

    /**
 * \defgroup ff_plugins_fuzzy_obj fuzzy obj.      <- group name and menu label
 * \ingroup ff_plugins                            <- parent group (the menu level above)
 *
 * This group contains form factors with many different fuzzy cross-sectional profiles.
 */

    A group with \toplvldescr{form factor,sasfit_ff,form_fac} is the root of a menu (here: the form factors); groups above it (model_functions) are not shown;

  • the plugin headers (pysasfit.studio.headers) name the group of every function with \ingroup.

    defs = load_groups() # all .def files; defs.files lists them top = build_menu(headers.catalogue().values(), (“sq”,), defs) for path, p in iter_functions(top): … # path: labels of the groups above p print(”n”.join(tree_lines(top)))

Groups without functions are left out. Functions without a (known) group are collected in a last entry, so nothing disappears when a .def file is missing; without any .def file the menu is a flat list.
