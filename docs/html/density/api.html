pyDENsity: API reference

Generated from the docstrings.

pyDENsity core: DENSS (DENsity from Solution Scattering, T. D. Grant, Nature Methods 15 (2018) 191) from pySASfit.

DENSS reconstructs a low-resolution electron-density map on a grid directly from a SAXS/SANS curve (iterative structure factor retrieval with shrink-wrap support). Unlike bead models it allows internal contrast and holes, and unlike spherical-harmonics envelopes it is not limited to star-shaped bodies.

DENSS is not part of pySASfit: it is a separate GPL-3.0 package (pip install denss, pure Python, needs numpy and scipy). pyDENsity runs it as a separate process (python -m denss.scripts...) and reads the files it writes; no DENSS code is imported into pySASfit.

from pysasfit.density import run_denss, run_denss_all r = run_denss((q_nm, I, dI), dmax_nm=10, mode=”FAST”) # one map; r.rho, r.voxel, r.rg, r.chi2, r.fit_* a = run_denss_all((q_nm, I, dI), dmax_nm=10, nmaps=20, cores=4) # 20 maps, aligned and averaged, FSC resolution

Units: pySASfit curves have q in 1/nm; DENSS works in 1/Å and Å. The data are written in 1/Å; results are given in Å (maps, Rg, volumes) as DENSS reports them, the fitted curve in 1/nm again.

Compatibility: DENSS 1.8.7 (the current release) uses np.in1d and np.trapz, which NumPy 2.4 removed, and passes a one-element array to struct.pack when writing MRC maps (denss.core.write_mrc, re-exported as denss.write_mrc), which NumPy 2.x rejects. The process is therefore started through a small shim (SHIM) that adds the two names (np.isin, np.trapezoid) and writes maps with a plain float box size, without changing the DENSS installation. The same patches are the sitecustomize of every run (a .pydensity folder in the run folder, first on PYTHONPATH), so that the worker processes of denss-all get them too: multiprocessing starts them as fresh interpreters on Windows and macOS.
