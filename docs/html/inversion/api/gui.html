pysasfit.inversion.gui.app

pyINVersion GUI (formerly pySASfitInversion): a thin Qt (PySide6) layer over the pysasfit.inversion library. No numerics live here – every computation (loading, background fitting/subtraction, kernel construction, solving) calls straight into the library, so the library stays usable headless/scriptable/testable on its own (see tests/test_gui_smoke.py, which drives this same MainWindow class programmatically with QT_QPA_PLATFORM=offscreen).

Layout (2026-11-07, as pySASred / pySASmorph): dockable panels – Data, Background, Inversion, Info (explanation of the control under the mouse and the details of the last load / background fit / solve), I(q) (data + background + fit, residuals) and Distribution. Every panel can be moved, stacked as tabs, detached into its own window and hidden (View menu); the arrangement is kept with the last session and in project files.

One text field for all explanations and detailed results (2026-10-10, replaces tooltips and inline hint labels). Shows exactly one text – the one of the control under the mouse, or the details of the last load / background fit / solve.

It is a panel of its own (by default below the controls), so its height can be dragged. required_height() is the height of the longest registered text at the current width: the panel never gets taller than that (maximum height) and, as long as the user has not dragged the splitter, it is kept at exactly that height. If it is made smaller, the text scrolls. on_required_changed(h) is called when the required height changes (width change, new data/background/result texts).

pysasfit.inversion.gui.help_texts

All explanatory texts shown in the GUI’s info panel.

Help texts for the GUI’s info panel (2026-10-10).

All explanatory text of the GUI lives here instead of in tooltips and inline hint labels. gui.app.InfoPanel shows exactly one of these entries – the one belonging to the control under the mouse (or the item highlighted in an open drop-down list) – and sizes itself to the longest entry, so the panel never needs to scroll or resize while hovering.

Keys:

plain names one entry per control (“r_max”, “spline”, …) “kernel:<key>” one entry per kernel of KERNEL_REGISTRY “solver:<key>” one entry per solver of SOLVER_REGISTRY “option:<name>” one entry per solver option (SolverSpec.options)

“{dynamic}” in a text is replaced by the GUI with current information (suggested grid values, the loaded data, background fit and solve results); the panel is resized to fit those texts too.

Texts are Qt rich text (a small HTML subset). Keep the first line a bold title; the panel layout relies on nothing else.
